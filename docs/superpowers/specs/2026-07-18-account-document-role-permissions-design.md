# 账号隔离、文档可见性与动态角色设计

## 目标

修复账号切换后残留上一账号聊天状态、历史会话加载后无法滚动的问题；让所有登录用户看到完整文档目录及其角色权限，同时继续在服务端严格限制内容访问；将固定角色选择扩展为可管理的动态角色。

## 账号与聊天状态

- 手动登出、401 自动登出和刷新令牌失败统一调用会话清理流程。
- 清理流程终止活动中的流式请求，并清空聊天记录、历史会话列表、当前会话 ID 和加载状态。
- 登录成功后只加载新账号自己的会话列表，不复用前一账号的 Pinia 状态。
- 服务端继续按 JWT 中的用户 ID 查询会话，客户端传入的用户 ID 不作为身份依据。

## 历史会话滚动

- 页面布局保证从应用容器到聊天主区域的 flex 高度链完整，滚动区域设置 `min-height: 0` 和 `overflow-y: auto`。
- 历史会话加载完成后等待 DOM 更新，重置贴底状态并将消息容器定位到底部。
- 新会话、历史切换和流式生成共用一个滚动状态更新入口。
- 用户主动向上滚动后，流式增量不强制抢回滚动位置，只显示“回到底部”按钮。

## 文档目录与权限

- `GET /api/knowledge/list` 对所有已认证用户返回指定知识库的全部文档元数据。
- 每个文档返回 `accessible`、`allowedRoles`。角色项包含 `roleCode` 和 `roleName`。
- 非管理员可以看到无权限文档的名称、类型、处理状态、创建时间和角色授权，但不能检索其内容。
- 前端对无权限文档显示锁定状态和“无访问权限”，禁用选择及问答入口。
- 向量检索继续通过当前用户可访问文档 ID 白名单过滤；空白名单必须匹配不到任何文档。
- 管理员可以编辑每份文档的角色授权。

## 动态角色

- 新增管理员角色管理接口：列表、新增、修改名称与描述、删除。
- `ADMIN` 为受保护的系统角色，不允许删除或修改角色编码；其管理权限仍由 `ROLE_ADMIN` 判定。
- 自定义角色只参与文档读取授权，不自动获得任何管理能力。
- 保持当前“一个用户一个角色”模型，用户新增和角色调整都从动态角色列表选择。
- 被用户引用的角色禁止删除，并返回明确提示；没有用户引用的自定义角色可删除，数据库外键级联清除其文档授权。
- 角色编码创建后不可修改，避免 JWT、用户关联和文档授权产生悬空引用。

## 接口与数据模型

- 新增 `RoleController`、`RoleService` 及角色创建/更新 DTO、角色展示 VO。
- `DocumentVO` 增加 `boolean accessible` 与 `List<RoleVO> allowedRoles`。
- `DocPermissionMapper` 支持批量查询文档授权角色，避免逐文档 N+1 查询。
- 前端新增角色 API 和角色 Pinia 状态，用户管理、上传权限、文档权限编辑共用同一角色来源。

## 错误处理

- 删除系统角色返回业务错误。
- 删除仍被用户使用的角色返回冲突提示，不做隐式用户迁移。
- 文档权限中包含不存在的角色时整次更新失败，不允许静默跳过造成部分授权。
- 历史会话或角色列表加载失败时清除对应加载状态，并保留可重试入口。

## 测试

- 前端测试覆盖登出清理、账号重新登录、活动流中止、历史加载后的滚动状态与无 `localStorage` 环境。
- 后端测试覆盖完整文档列表、`accessible` 计算、授权角色映射、空权限检索拒绝。
- 角色服务测试覆盖新增、重复编码、更新、系统角色保护、被用户引用时禁止删除及安全删除。
