# 本地启动

> 适用场景：Windows 本机开发，机器上没有 Docker / WSL，中间件用便携版直接跑进程。
> 云端部署见 [deployment.md](deployment.md)；密钥处理原则见 [07-安全与密钥.md](07-安全与密钥.md)。

## 一、端口与依赖

| 组件 | 版本 | 端口 | 说明 |
| --- | --- | --- | --- |
| PostgreSQL + pgvector | 17.6 + 0.8.6 | 5432 | 库 `smrag`，向量表与业务表都由 Flyway 建 |
| Kafka（KRaft 单节点） | 3.9.1 | 9092 | 文档解析任务队列 |
| MinIO | RELEASE.2025-10-15 | 9000 / 9001 | 9000 为 S3 API，9001 为控制台 |
| 后端 smrag-core | Spring Boot 3.5.8 | 8080 | `smrag-core/target/smrag-core-1.0.0-SNAPSHOT.jar` |
| 前端 smrag-web | Vite | 3000 | `/api` 反向代理到 8080 |

本机中间件是便携版解压安装，位于 `D:\Middleware`，**未注册 Windows 服务**，所以每次重启机器后都要手动拉起。

可复用的运维脚本：

```powershell
powershell -ExecutionPolicy Bypass -File D:\Middleware\scripts\status.ps1      # 查看各端口与连通性
powershell -ExecutionPolicy Bypass -File D:\Middleware\scripts\start-all.ps1   # 启动全部中间件
powershell -ExecutionPolicy Bypass -File D:\Middleware\scripts\stop-all.ps1    # 优雅停止
```

`start-all.ps1` 会连 MySQL、Redis、Elasticsearch、Neo4j 一起启动，这四个服务本项目用不到。只做本项目开发时，按下面第二节的命令单独起三个即可，省内存。

## 二、启动顺序

### 1. 中间件（PostgreSQL / Kafka / MinIO）

```powershell
# PostgreSQL
Start-Process -FilePath 'D:\Middleware\postgres\pgsql\bin\postgres.exe' `
  -ArgumentList @('-D','D:\Middleware\data\postgres') -WindowStyle Hidden `
  -RedirectStandardOutput 'D:\Middleware\logs\postgres-stdout.log' `
  -RedirectStandardError  'D:\Middleware\logs\postgres-stderr.log'

# MinIO
Start-Process -FilePath 'D:\Middleware\minio\minio.exe' `
  -ArgumentList @('server','D:\Middleware\data\minio-data','--address',':9000','--console-address',':9001') -WindowStyle Hidden `
  -RedirectStandardOutput 'D:\Middleware\logs\minio-stdout.log' `
  -RedirectStandardError  'D:\Middleware\logs\minio-stderr.log'

# Kafka：本机 .bat 启动器会报 The input line is too long，直接用 java 启动
Start-Process -FilePath 'D:\DevTools\jdk21\bin\java.exe' `
  -ArgumentList @('-Xmx1G','-Xms512M',
    '-Dkafka.logs.dir=D:\Middleware\kafka\kafka_2.13-3.9.1\logs',
    '-Dlog4j.configuration=file:D:\Middleware\kafka\kafka_2.13-3.9.1\config\log4j.properties',
    '-cp','D:\Middleware\kafka\kafka_2.13-3.9.1\libs\*',
    'kafka.Kafka','D:\Middleware\kafka\kafka_2.13-3.9.1\config\kraft\server-nexus.properties') -WindowStyle Hidden `
  -RedirectStandardOutput 'D:\Middleware\logs\kafka-stdout.log' `
  -RedirectStandardError  'D:\Middleware\logs\kafka-stderr.log'
```

自检：执行 `status.ps1`，Kafka、MinIO、PostgreSQL 三行应为 `UP`。

### 2. 建库（仅首次）

Flyway 会在后端启动时自动执行 `smrag-core/src/main/resources/db/migration/` 下的脚本，但**数据库本身要先建出来**：

```powershell
$env:PGPASSWORD = '<本机 postgres 口令>'
& 'D:\Middleware\postgres\pgsql\bin\psql.exe' -w -h 127.0.0.1 -U postgres -d postgres `
  -c "CREATE DATABASE smrag WITH OWNER = postgres ENCODING = 'UTF8';"
```

库名、账号与口令要和 `smrag-core/src/main/resources/application.yml` 的 `spring.datasource` 保持一致。库已经存在时跳过本步。

### 3. 环境变量

后端启动**必须**提供 `DASHSCOPE_API_KEY`（阿里云百炼），否则 `spring.ai.dashscope.api-key` 解析不到占位符，应用直接启动失败：

```powershell
$env:DASHSCOPE_API_KEY = '<百炼 API Key>'
```

首次启动还需要 `SMRAG_SECURITY_BOOTSTRAP_ADMIN_PASSWORD`：

- 迁移脚本 `V11__lock_seeded_admin_password.sql` 会把种子管理员 `admin` 的口令置为锁定值，首次启动由 `BootstrapAdminInitializer` 用该变量写入真实口令，**长度至少 12 位**；
- 初始化完成后该账号口令已在库里，后续启动不再需要这个变量；
- 默认 profile 下的变量名是 `SMRAG_SECURITY_BOOTSTRAP_ADMIN_PASSWORD`（对应属性 `smrag.security.bootstrap-admin.password` 的松散绑定）。启动失败信息里提示的 `SMRAG_BOOTSTRAP_ADMIN_PASSWORD` 只在 `prod` profile（`application-prod.yml`）下生效，照抄会继续启动失败。

### 4. 后端

```powershell
# 构建（首次或代码有改动时）
mvn -f pom.xml -pl smrag-core -am package -DskipTests

# 启动
java -jar smrag-core\target\smrag-core-1.0.0-SNAPSHOT.jar
```

如果希望后端在后台常驻、日志落盘，可以改用：

```powershell
Start-Process -FilePath 'java' `
  -ArgumentList @('-jar','D:\FangdeRepos\smrag\smrag-core\target\smrag-core-1.0.0-SNAPSHOT.jar') `
  -WorkingDirectory 'D:\FangdeRepos\smrag' -WindowStyle Hidden `
  -RedirectStandardOutput 'D:\Middleware\logs\smrag-backend-stdout.log' `
  -RedirectStandardError  'D:\Middleware\logs\smrag-backend-stderr.log'
```

日志出现 `Started SmragApplication` 与 `Tomcat started on port 8080` 即启动成功。

### 5. 前端

```powershell
cd smrag-web
npm install    # 仅首次
npm run dev
```

Vite 监听 `http://localhost:3000`，把 `/api` 代理到 `http://localhost:8080`。

## 三、本地自检

| 检查项 | 命令 | 期望结果 |
| --- | --- | --- |
| 后端健康 | `Invoke-WebRequest http://localhost:8080/actuator/health` | `{"status":"UP"}` |
| 登录接口 | `curl.exe -sS -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"<口令>\"}"` | `code` 为 200，`data.accessToken` 有值 |
| 前端代理 | 把上一条的地址换成 `http://localhost:3000/api/auth/login` | 同样返回 200，说明代理链路通 |
| MinIO bucket | `MC_HOST_local='http://<账号>:<口令>@127.0.0.1:9000'` 后执行 `D:\Middleware\minio\mc.exe ls local` | 后端首次启动自动创建 `super-agent-document` |
| Kafka topic | 见下方命令 | 存在 `document-parse` |

```powershell
java -cp "D:\Middleware\kafka\kafka_2.13-3.9.1\libs\*" org.apache.kafka.tools.TopicCommand --bootstrap-server localhost:9092 --list
```

`document-parse` 主题由消费者订阅时自动创建；`document-parse.DLT` 在有解析失败进入死信时才出现。

## 四、停止

```powershell
# 按端口停后端 / 前端（8080、3000）
Get-NetTCPConnection -LocalPort 8080 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

# 停全部中间件
powershell -ExecutionPolicy Bypass -File D:\Middleware\scripts\stop-all.ps1
```

直接关终端不会停掉用 `Start-Process -WindowStyle Hidden` 起的进程，需要用上面的方式显式结束。

## 五、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Kafka 的 `.bat` 启动器报 `The input line is too long` | 本机 `.bat` 对长 classpath 处理异常 | 用第二节的 `java -cp ... kafka.Kafka server-nexus.properties` 方式启动 |
| 启动报 `Set SMRAG_BOOTSTRAP_ADMIN_PASSWORD before starting FundRAG` | 默认 profile 下变量名不对 | 改用 `SMRAG_SECURITY_BOOTSTRAP_ADMIN_PASSWORD`，且不少于 12 位 |
| 日志出现 `error response NOT_COORDINATOR` | 单节点 Kafka 首次建消费者组时的短暂重试 | 观察数秒内自行恢复，无需处理 |
| 启动报占位符 `DASHSCOPE_API_KEY` 无法解析 | 没有设置该环境变量 | 设置后重启后端 |
| 问答报鉴权或额度错误 | 用了占位 Key 或 Key 失效 | 换真实 Key 后重启后端 |
| 8080 / 3000 端口被占用 | 上一次进程未正常退出 | 按第四节按端口结束进程后重启 |

## 六、与云端部署的差异

- 云端走 `compose.prod.yml` + `.env.prod`，`SPRING_PROFILES_ACTIVE=prod`，数据库口令、JWT 密钥、MinIO 口令全部由环境变量注入。
- 本地默认 profile 的连接串与 MinIO 账号写在 `application.yml` 里，只适用于本机开发，任何共享环境都不得沿用。
- 本地只跑单实例，没有 Caddy、没有 HTTPS、没有备份脚本；上线前按 [deployment.md](deployment.md) 走完整验收。
