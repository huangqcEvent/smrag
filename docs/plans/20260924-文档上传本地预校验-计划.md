## 验证计划

| 验收标准 | 验证方式 | 证据形式 |
| --- | --- | --- |
| R1-1 超限文件不发请求且有提示 | `node --test tests/uploadGuard.test.js` 断言 `TOO_LARGE` 分支与边界值；页面接入点用 `npm run build` 证明模板与脚本可编译 | 测试原始输出 + 命令记录 |
| R1-2 合规文件行为不变 | 回归既有用例（`documentChunking`、`documentFileRequest` 等）并对比基线 | 回归对比表 |
| R1-3 边界值 20971520 通过 | 测试中显式包含 `MAX_UPLOAD_SIZE_BYTES` 与 `+1` 两个用例 | 测试原始输出 |
| R2-1 空文件被拦截 | 测试中断言 `EMPTY` 分支 | 测试原始输出 |
| R2-2 提示口径与后端一致 | 人工比对后端 `DocumentService#validateFile` 与 `uploadGuard.js` 的判定顺序，写入验收报告 | 代码位置对照 |
| R3-1/R3-2 常量值正确且只有一处 | `rg` 检索 `20971520` 在 `smrag-web/src` 下的出现位置 | 检索命令与输出 |

**证据形式说明**：本需求是纯逻辑前置校验，判定发生在请求发出之前，没有可截图的界面差异（页面无新增元素，提示为一次性 toast），因此证据以「可复现的命令 + 原始输出」为主。界面表现要在有后端与登录态的环境里才能观察，属本计划未覆盖项，已在验收报告中显式说明。
